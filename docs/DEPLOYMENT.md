# النشر والتحديث

## المسار العام

يستخدم زر النشر المستودع العام `MowaridStore/mowarid-store` وملف `wrangler.toml`. Workers Builds ينفذ البناء ثم أمر `npm run deploy`. يعرض `.dev.vars.example` اسم سر التثبيت فقط، بقيمة فارغة؛ يختار صاحب المتجر قيمته داخل Cloudflare. لا يحتاج إلى تعديل معرف قاعدة البيانات أو أسماء حاويات التخزين يدويًا.

أداة `scripts/deploy-cloudflare.mjs`:

1. تفحص أسماء موارد هذه النسخة في حساب النشر. إذا كانت قاعدة D1 موجودة ولم يُحفظ معرّفها في إعدادات القالب، تربطها بمعرّفها بدل إعادة إنشائها. تحافظ على المعرّفات المحددة وأسماء مخازن الصور والنسخ الاحتياطية، وتستخدم إعدادًا مؤقتًا دون تغيير ملف المصدر. تنشر Worker وتجهز تلقائيًا الموارد الناقصة وDurable Objects.
2. تحفظ عنوان المتجر المعتمد `APP_ORIGIN` تلقائيًا من رابط Cloudflare، وتحافظ عليه في النشر اللاحق أو تستخدم القيمة التي خصصتها في الإعدادات.
3. تطبق ملفات `migrations/` الناقصة على DB دون استيراد Fixtures.
4. تفحص وجود حساب وطلبات واعتمادات مخزنة ووجود أسماء مفاتيح التشفير.
5. تولد `ENCRYPTION_KEY` و`AUTH_PEPPER` عشوائيًا لأول متجر فارغ فقط، وتنشرهما كأسرار. لا تُطبع قيمهما. إذا كان متجر قائم فقد مفاتيحه تتوقف الأداة وتطلب استعادة الأصل، دون تدويرها وإفساد البيانات.
6. تتحقق من عنوان المتجر القائم قبل تغييره؛ في متجر فارغ جديد تستعمل رابط النشر الذي يعيده Cloudflare دون انتظار اسم النطاق قبل تجهيز المفاتيح. بعد النشر تنتظر وصول النسخة الجديدة وعنوانها الصحيح، بما في ذلك حالات تأخر DNS أو ظهور استجابة النسخة السابقة. تعرض رابط الإدارة بعد نجاح التحقق. ينشئ المالك حسابه باستخدام رمز التثبيت الخاص وTurnstile الخاص به.
7. عند الفشل تعرض العملية ورسالة Cloudflare الفعلية مع إخفاء قيم الأسرار. إعداد التثبيت المؤقت والملف المؤقت للمفاتيح يُحذفان عند انتهاء الأداة.

المصدر لا يحتوي على معرف حساب الناشر، أو مفاتيح مورد وMeta، أو بيانات زبائن. R2 للصور والنسخ خاص؛ خدمة الصور تمر عبر Worker. النسخ مشفرة. لا تشارك ملف استرداد المالك.

إن توقف التثبيت، راجع سجل Workers Builds والصلاحيات وتفعيل R2 ثم أعد المحاولة. لا تحذف الموارد لإصلاح خطأ نشر. يحتاج أول نشر كامل إلى اكتمال تحديثات القاعدة والأسرار قبل إنشاء الحساب.

## التحديث

- حدّث كود مستودع نسختك مع إبقاء اسم Worker وموارد D1 وR2 والروابط القائمة.
- احفظ نسخة احتياطية ومفاتيح الاسترداد الأصلية قبل التحديث.
- Workers Builds يعيد البناء والنشر عند دفع التحديث إلى الفرع المرتبط. لا يجلب تحديث المستودع الأصلي تلقائيًا.
- أداة النشر لا تستبدل الإعدادات أو المنتجات أو أسعار الطلبات التاريخية، ولا تستورد ملفات التجربة.
- لا تحذف `ENCRYPTION_KEY` أو `AUTH_PEPPER` عند تحديث المتجر. استعادة قاعدة مشفرة إلى موارد جديدة تتطلب المفتاح الأصلي؛ راجع `scripts/restore-backup.mjs`.

كل مشروع يحافظ على نطاقه `.workers.dev`. لإضافة دومين تملكه، استخدم Workers & Pages → مشروعك → Settings → Domains & Routes → Custom Domain بعد ربط النطاق بـ Cloudflare. أضف النطاق إلى Turnstile واضبط `APP_ORIGIN` إن كنت تستخدم نطاقًا أساسيًا ثابتًا. إضافة دومين لا تحتاج إنشاء قاعدة جديدة.

روابط الحملات تقبل الدومين المربوط تلقائيًا بعد التحقق من نفس نسخة المتجر، دون تغيير `APP_ORIGIN` لهذا الغرض. احتفظ بعلم التوافق `global_fetch_strictly_public` في إعدادات Worker لتمرير التحقق عبر الدومين العام وفق [توثيق Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/fetch/).

## النشر اليدوي للمطور

```sh
npm ci
npm run build
npx wrangler login
npx wrangler secret put SETUP_TOKEN
npm run deploy
```

R2 يحتاج التفعيل، والموارد والخدمات تخضع لحصص Cloudflare. لا نضمن أن زيادة الاستخدام تبقى مجانية. النسخة تستخدم SQLite Durable Objects الخاصة للدخول والمهام، المتاحة على Workers Free ضمن الحصص الحالية. [زر النشر الرسمي](https://developers.cloudflare.com/workers/platform/deploy-buttons/)، [أسرار Workers](https://developers.cloudflare.com/workers/configuration/secrets/).

`wrangler.pages.toml` و`wrangler.jobs.toml` يدعمان مسار التطوير القديم؛ المسار العام يستخدم Worker واحدًا من `wrangler.toml`. أداة `deploy:live` تخص المشرف وملفاته الخاصة المتجاهلة في Git، وليست خطوة مطلوبة للمتدرب.
