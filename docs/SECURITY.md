# حدود الأمان والتشغيل

## المصادقة

كلمة مرور جديدة تتطلب 8 أحرف إلى 128 تتضمن حروفًا وأرقامًا؛ لا تُفرض الرموز الخاصة أو اختلاف حالة الحروف. كلمات مرور الحسابات القائمة لا تتغير.

في مسار النشر الفعلي عبر `wrangler.toml`، تمر كلمة المرور أولًا عبر HMAC-SHA256 بمفتاح AUTH_PEPPER منفصل عن D1، ثم scrypt بملح عشوائي من 16 بايت، وإعدادات N=32768 وr=8 وp=3، وكلفة ذاكرة 32MiB. تُخزن النتيجة في D1. الحساب يجري داخل Durable Object خاص متاح فقط عبر binding، دون تخزين مدخلات أو طباعتها. لا نخزن كلمة المرور أو مشتقًا قابلًا للاستعمال مباشرة بدلها. الجلسات تحتوي رموزًا عشوائية وتُخزن تجزئتها. مدة الجلسة 30 يومًا، وتتجدد مع استعمال الإدارة بحد أقصى مرة كل 24 ساعة؛ يتجدد Cookie أيضًا مع الحفاظ على HttpOnly وSecure وSameSite=Strict. لا يعيد التجديد إنشاء جلسة منتهية أو ملغاة. يسمح الحساب بجلسات مستقلة على عدة أجهزة ولا يرتبط استمرارها بعنوان IP؛ الدخول من جهاز جديد لا يغلق غيره، والخروج يبطل جلسة الجهاز الحالي فقط. تغيير كلمة المرور يبطل الجلسات ويجدد رموز الاسترداد أحادية الاستخدام. تسجيل الدخول مستقل لكل متصفح ولكل دومين؛ الانتقال بين `.workers.dev` والدومين الخاص لا ينقل Cookie بينهما.

هذه إعدادات scrypt ضمن الملفات الموصى بها من OWASP. نقل الحساب إلى Durable Object يتجنب حد CPU الخاص بطلب Worker العام، مع بقاء الحماية الإضافية عبر Pepper وكلمة مرور طويلة وTurnstile وحد المحاولات. هذه الموارد متاحة على Free باستخدام backend SQLite؛ لها حصص مستقلة يجب مراقبتها. لا يُعرض مسار HTTP عام لتشغيل التجزئة أو المهام. [توصية OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)، [حدود Durable Objects](https://developers.cloudflare.com/durable-objects/platform/limits/)، [التسعير](https://developers.cloudflare.com/durable-objects/platform/pricing/).

الاختبارات المحلية تستخدم إعدادات إنتاج وscrypt الأصلية داخل Durable Object. لا يُعد ذلك قياسًا سحابيًا؛ أداة النشر تفحص المسار على الرابط المنشور قبل فتح إنشاء حساب المالك. تسجيل الدخول الإنتاجي يرفض غياب PASSWORD_HASHER ولا يستخدم PBKDF2 داخل Worker العام. PBKDF2-SHA256 القديم ب600 ألف دورة يبقى للتطوير المحلي دون binding فقط؛ الحسابات القديمة المدعومة يمكن ترحيلها إلى scrypt بعد دخول صحيح، وإذا رفض runtime إعدادات PBKDF2 القديمة يستخدم المالك الاسترداد، دون تخفيف كلفتها.

لا يُفتح إنشاء المالك لمن يعرف الدومين فقط: يتطلب عبارة SETUP_TOKEN الخاصة التي يختارها المالك في Cloudflare. يُبادل الرمز بملف Cookie مؤقت HttpOnly وSecure وSameSite=Strict ويُغلق التجهيز عند إنشاء الحساب. تُفحص مفاتيح Turnstile الخاصة بالمتدرب قبل إنشاء الحساب، ويُشفّر Secret Key في D1. ينزّل المالك ملف الاسترداد؛ النسخة الأولى تتضمن مفتاح استعادة النسخ الاحتياطية الخاص بمتجره، ولا يظهر هذا المفتاح في إعدادات الإدارة أو المتجر العام. لا توجد أسرار مشتركة بين المتاجر. مسار مشرف النشر القديم يدعم رابط تجهيز خاص أيضًا.

## الطلبات والأسرار

- الطلبات المعدّلة تحتاج Origin صحيحًا؛ العمليات الإدارية تحتاج جلسة وCSRF أيضًا.
- أسرار الربط مشفرة بـAES-256-GCM، ولا تعاد إلى المتصفح بعد الحفظ. النسخ الخاصة مشفرة بالمفتاح نفسه؛ لا تجعل bucket النسخ عامًا.
- العميل لا يحدد سعر التحصيل أو المورد. الخادم يعيد الحساب، ويثبت لقطة الطلب، ويتحقق من تطابق المورد مجددًا قبل التوريد.
- معرّف الطلب الخارجي لا يتغير عند إعادة المحاولة، ويُستعلم عنه أولًا لتسوية النتائج غير المعلومة. قبول HTTP 200 وحده لا يعني إنشاء شحنة.
- رفع الصور يقبل WebP فقط بحد الحجم وفحص التوقيع، بعد إعادة ترميزها في متصفح المسؤول. وصف HTML يمر بقائمة سماح على الخادم للوسوم والروابط وCSS الآمن؛ تُزال السكربتات ومعالجات الأحداث والإطارات والنماذج والتموضع الذي قد يغطي واجهة الطلب. محرر الوصف ومعاينة المسودة يعملان داخل iframe لا يسمح بتشغيل السكربتات، واللصق المنسق يُنقّح قبل عرضه.
- يمكن لصق كود بكسل Meta في اللوحة لاستخراج معرّف واحد فقط؛ لا يُخزن الكود ولا يُنفذ. الصور المرفوعة تُقرأ من bucket الصور فقط عبر `/media/<uuid>.webp` مع تخزين مؤقت؛ bucket النسخ مستقل وخاص.
- تعمل البكسلات المهيأة عند وصول الزائر دون نافذة موافقة. يرسل CAPI أحداث الويب بمعرّفات مشتركة مع البكسل لإزالة التكرار، وLead بعد حفظ الطلب، وPurchase بعد دليل التوصيل فقط. حمولة طابور الويب مشفرة، تمسح بعد قبول Meta وتحذف سجلاتها بعد سبعة أيام. لا يقبل مسار المتصفح أحداث Lead أو Purchase. رمز CAPI مشفر ومتاح على السيرفر وحده؛ لا نرسل الاسم أو الهاتف إلى Google Analytics.
- حدود المحاولات تستخدم تجزئة مرتبطة بالمفتاح لعنوان IP. سجلات التدقيق لا تحفظ الأسرار.

## قبل توسعة الاستخدام

أعد قياس CPU وأحجام البيانات والحصص باستخدام الكتالوج والصور الحقيقية. سياسات الخصوصية والاسترجاع الافتراضية تحتاج مراجعة المالك قبل النشر. راقب صلاحية مفاتيح الإعلانات ونسخ API؛ تتغير خارجيًا وقد تحتاج تحديث التكامل مستقبلًا.

الإسناد من UTMs يساعد التقارير لكنه ليس دليلًا مضمونًا على مصدر كل بيع. حجب التتبع واختلاف نوافذ الإسناد وتأخر التسليم يؤثر على نتائج المنصات.

الدخول في الواجهة بالبريد وكلمة المرور، والاستعادة بملف الاسترداد أو رمز محفوظ فقط. أزيلت خيارات البصمة من الدخول والتجهيز وحساب المالك، وعُطلت مسارات API لتسجيل مفاتيح WebAuthn أو استعمالها للدخول والاستعادة؛ السجلات القديمة لا تُحذف صامتًا. استعادة الحساب بالملف تبطل الرموز السابقة والجلسات ومفاتيح الدخول القديمة وتصدر ملفًا جديدًا. لا توجد خدمة بريد لاستعادة الحساب مُفعّلة افتراضيًا.

رفع WebP يفحص أبعاد الملف الفعلية ويمنع الصور المتحركة والأبعاد المزورة، ويحد الحجم إلى 2MB والأبعاد إلى 2000×16383 بكسل ومساحة الصورة إلى 24 مليون بكسل. المتصفح يحافظ على WebP المناسبة كما هي لتجنب تقليل وضوح الصور الطويلة.
